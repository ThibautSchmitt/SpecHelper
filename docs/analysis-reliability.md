# Evidence and independent analysis

The reliability protocol separates an analyst, an independent counter-analyst
and a verifier. The counter-analyst forms its own source-based view before seeing
the analyst's conclusions. The verifier reconciles the reports and checks decisive
claims; the analyst cannot approve its own work. Distinct contexts remain required
when one connected account performs all roles. Available model families may vary;
a missing second family must be visible rather than invented.

An answer distinguishes verified facts, interpretations, business decisions,
contradictions and unknowns. Each decisive factual claim needs traceable evidence
at the frozen Git baseline, or a scoped read-only database observation. Evidence
records its context and limits. No numeric confidence score replaces evidence.

## What the reviewers check

For a claim such as “all orders can be cancelled,” identify the subject, universal
quantifier, applicable time, population, configuration and exceptions. Search for
counterexamples and alternate entry points. A branch guarded by configuration does
not establish an unconditional rule. An older import or historical anomalous row
does not establish what current validated code allows.

A configured database can corroborate or contradict a material claim through
small counts, existence checks or distributions. It remains optional: unavailable
access, absent data and inconclusive results must be disclosed. Never request
unnecessary business rows merely to make an answer appear stronger. Credentials
remain outside prompts, sources remain read-only, and existing capability and
environment restrictions continue to apply.

If a material contradiction remains, perform a targeted check or request guided
business clarification. An unresolved business decision stays explicit; a reviewer
must not silently select a policy. Technical facts and a user's intended business
rule are different forms of evidence.

## Efficient navigation

The reusable `effective-navigation` skill locates relevant symbols, callers,
configuration and entry points before reading bounded source ranges. It follows
exceptions and temporal boundaries, and expands its search whenever evidence is
insufficient. Compact structured findings replace copied files and long repeated
dialogues. Efficiency never permits skipping independent review or decisive proof.

Existing customized library content is preserved. Seeding a reusable skill does
not grant a connection a new capability or widen environment access. Structural
indexes are navigation hints tied to exact authorized source snapshots; reviewers
still reopen actual files. See the [optional index evaluation](index-evaluation.md)
for reproducible fixtures, measured observations and current evidence gaps.

## Operational limits

Existing sequential queue behavior remains: distinct requests retain separate
contexts; a request already running cannot start a competing analysis. Shared
provider quota can delay work across browsers. The current phase and public role
explain progress, while unavailable quota or missing evidence must remain visible.

Reliable behavior is tested at the protocol and evidence boundaries. Controlled
test responses establish orchestration behavior; they do not establish the real
provider's factual accuracy. The acceptance report must state those limits.
